# 2026-10-24

## Phase 6 hardening + legacy import

- Added durable login throttling in `rate_limit_buckets`: SHA-256 email+IP key, 10 attempts / 10 minutes, atomic PostgreSQL upsert, cleared after successful login. `NUXT_TRUST_PROXY=false` by default; `X-Forwarded-For` is trusted only when explicitly enabled behind a proxy that overwrites it.
- Added browser hardening headers: HSTS, `X-Permitted-Cross-Domain-Policies: none`, plus existing frame/nosniff/referrer/permissions headers.
- `/api/health` now probes the database and returns `database: ok|unavailable` while preserving `service` and `timestamp`.
- CI now runs typecheck, tests, and a production build.
- Legacy import pipeline:
  - staging batches + per-source-row payload/hash provenance
  - validation, dry-run, apply, source-row reports, duplicate/conflict reporting
  - deterministic target UUIDs, idempotent replay, reconciliation totals
  - fixed-point invalidation of dependent rows even when parents are listed later
  - unknown top-level snapshot tables are rejected instead of silently ignored
  - strict status/type/method/financial timestamps; no silent financial defaults
  - closed cash deposits require `dispositions`; document-custody deposits cannot have cash dispositions
  - duplicate source IDs are reported without failing staging (non-unique staging index)
  - unique conflicts that are not idempotent replays abort the batch instead of being silently skipped
  - imported motorcycles receive fresh QR credentials; imported agreements get a version-1 immutable snapshot with `changeReason: imported`
  - owner/admin API `POST/GET /api/imports/legacy`; CLI `npx tsx apps/web/scripts/import-legacy.ts`
- Dev PGlite migration `0018_icy_living_mummy.sql` applied; staging index manually changed from `legacy_import_rows_batch_source_uidx` to non-unique `legacy_import_rows_batch_source_idx`.
